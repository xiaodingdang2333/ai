# 番茄小说人工发布协作流程

更新日期：2026-06-27

## 当前默认分工

- AI：写作、更新大纲和追踪文件、本地质检、上传新增章节到正确草稿箱、核验平台草稿。
- 用户：在番茄作者后台检查草稿并手动发布。
- 不创建或启用小说定时发布任务，不提供小说“立即运行一次”自动发布入口。
- 用户要求“继续写”时，默认在质检通过后上传草稿，但绝不自动发布。

## 已出现过的问题

1. 浏览器自动点击会因页面结构、按钮状态或弹窗变化卡在“下一步”或“确认发布”。
2. 同一作者账号的多本书共用浏览器端口和登录缓存，并发运行会互相阻塞。
3. 网页任务超时后，浏览器子进程和锁可能继续存活，影响后续任务。
4. 草稿为空时脚本曾以成功状态退出，但实际上没有发布任何章节。
5. Snap Chromium 的账号缓存隔离不稳定，存在识别错账号和传错作品的风险。
6. 草稿曾出现重复、无标题、章节匹配错误或平台字数异常。
7. 重复正文、“补记”等内容问题会被无人值守发布流程直接放大。

## 上传和停止规则

1. 上传前检查每章不少于 2500 中文字符，通常约 3000 字。
2. 检查章节编号、标题与内容匹配、标题未混入正文、正文无重复或拼接异常。
3. 上传前核对作者账号、完整书名和番茄作品 ID。
4. 只上传本次新增且平台不存在的章节，不自动删除、覆盖或修复已有草稿。
5. 上传后从草稿列表逐章核对章节号、标题和非零且合理的平台字数。
6. 发现账号不符、重复、缺失、无标题或字数异常时立即停止，不发布、不盲目重传，并向用户报告。

## 2026-07-04 长批量上传卡死

- 症状：第4至37章任务长期停在`running`，平台实际已有部分草稿，但数据库全部显示`uploaded=0`。
- 根因：包装器逐章启动Node且只在整段结束后回写；账号识别和单章CDP调用没有硬超时，任一环节卡住会无限等待。
- 修复：单次Node连接处理整段；每章验收后输出JSON心跳并立即更新`uploaded`和任务进度；账号识别限时60秒；连续240秒没有章节进度时终止并返回`failed`；失败保留最后成功章节清单，后续按检查点幂等续传。
- 验证：《太庙供着我的假牌位》1至7章识别为已发布，8至37章识别为平台草稿，1至37章服务器标记全部已验收，最终任务完成。
- 【已废弃：旧自定义GPT Action流程】旧网页规则曾要求拿到上传任务ID后持续调用`getNovelJob(wait_seconds=35)`直到终态；该规则不再作为当前网页版小说生产执行依据。番茄上传仍可由服务器脚本直接执行和验收，但不再通过旧网页Action主线组织。

## 2026-07-11 网页QA假通过与浏览器运行环境

- 症状：网页CH003声称Strong QA通过，但服务器current-blob P0实测249段、最长短段链40、最长锯齿链40；服务器重启后番茄浏览器又因Xvfb和root运行目录缺失无法启动。
- 根因：模型文字审稿被误当成机器证据；网页事务依赖整本累积账本；Xvfb未配置开机服务，Snap Chromium无法自行创建`/run/user/0/snap.chromium`。
- 失败方法：只改审稿说明、凭Markdown PASS推进、要求网页整体重写`08_章节事实账本.md`、在缺少X11运行环境时直接启动浏览器。
- 修复：网页正文先进入`FORMAL_WRITTEN_PENDING_MACHINE_P0`；服务器绑定当前Git Blob运行P0/READY；新章使用`章节事实账本/CHxxx.json`；恢复器核对分片、SHA、机器证据和state_applied；启用`xvfb-99.service`并由浏览器租约修复root运行目录。
- 平台验收：账号`西大水怪`，作品《她们都以为我只救了她》，第001—003章均由`fanqie-upload.js verify`返回`VERIFIED_DRAFT`，未自动发布。
- 防复发：上传worker每分钟扫描待机器P0和待上传事务；上传前再次独立重跑P0/READY；ChatGPT与番茄浏览器串行租约；建书先检查平台月度额度。
- 补充：ChatGPT浏览器使用持久`chatgpt-web-browser.service`，番茄租约结束后必须等待9224恢复；不得再使用会被回收的临时`systemd-run --collect`恢复方式。
