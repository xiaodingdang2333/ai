- 2026-06-04: GitHub push troubleshooting on this Windows workspace: if `git push origin main` over HTTPS hangs, first clear stale `git`, `git-remote-https`, and `git-credential-manager` processes, then test proxy/read path with `git ls-remote --heads origin main`. In the observed case, direct `github.com:443` failed, proxy `127.0.0.1:7897` worked, `ls-remote` succeeded, but `push --dry-run` hung because Git Credential Manager stalled. Disabling credentials (`git -c credential.helper= push --dry-run origin main`) returned `could not read Username`, confirming an auth/GCM issue rather than repository/network write size. SSH auth was already valid (`ssh -T git@github.com` returned the GitHub username), so pushing with `git push git@github.com:xiaodingdang2333/ai.git main` succeeded; then run `git fetch origin main` to refresh `origin/main`.

- 2026-07-03: A female ancient-romance market study produced 0 usable samples across 75 books, but the books were not all unavailable. Root cause: the Action backend forced the complete search + chapter fetch + packet build into a 30-second per-book timeout; a known downloadable book took about 27.5 seconds when idle and exceeded 30 seconds under concurrency. The packet builder also aborted an entire book when any selected mirror chapter was under 100 characters. Fix: raise the resource-bounded per-book timeout to 60 seconds while retaining adaptive 1-3 concurrency, 480-second batch cap and stop-at-6 behavior; skip bad chapter pages and try nearby chapters, requiring at least three usable chapters before accepting a packet. End-to-end rerun of the previously failed Fanqie batch completed in 73 seconds with 6 usable samples. Treat mass timeout failures as an infrastructure signal, not evidence that all ranking books are unavailable.
